# Threads @1fatherx — annual campaign

## Comment auto replies

`autoresponder.py` replies publicly to new external comments on the owner's own root posts. It randomly selects exactly `DM gw ya kak.` or `DM gw. thanks`, and stores the selected wording with the durable reply receipt. Own comments, hidden comments, comments before the configured cutoff, and comments already answered by the owner are skipped. An ambiguous publish response is held until the visible owner reply reconciles it; it is never blindly retried.

The separate `auto-replies.yml` worker uses a serialized self-dispatch chain. `mode=start` performs a normal bounded reply scan and immediately starts the first `mode=watch` worker. Each watch worker scans once, then dispatches a fresh worker around fifteen minutes after its cycle began. Each successor loads the latest repository, credentials and `AUTO_REPLY_ENABLED` variable. The off-hour GitHub cron remains a recovery fallback, rather than the primary clock. GitHub runner/dispatch outages can still delay checks. Turning `AUTO_REPLY_ENABLED` off prevents replies and continuation; cancelling a running job also skips its handoff. The same concurrency group and durable reply receipts prevent overlapping or repeated sends.

The 29 October repair followed observed multi-hour gaps in the nominal fifteen-minute cron: only two timer scans ran overnight, leaving a new eligible comment waiting. The missed comment was sent through the existing official-API worker before activating the new clock. `AUTO_REPLY_ENABLED` remains separate from `PUBLISH_ENABLED`; post scheduling, wording, the original activation cutoff, reply caps and ambiguous-send protections are preserved. `check`, `scan` and `run` remain one-off commands. Threads permissions were verified on 28 October, and a published reply was re-read from Threads on 29 October. No new OAuth consent is required.

Comments are processed in bounded scan cycles; a thread can wait for the next cycle if the per-run API budget is used up. The two exact owner templates are unchanged. Standard Ubuntu runners remain in the existing public repository; no additional hosting service is introduced.

Owner consent tooling: `TOOLS/connect_reply_permissions.py prepare`, then `exchange` after consent and `activate` after a successful cloud permission check. Tools live in the active local package, outside this cloud checkout. No plaintext token or app secret is committed.
